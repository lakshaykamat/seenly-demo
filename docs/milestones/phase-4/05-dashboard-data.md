## Navigation restructure

The sidebar goes from a flat list to grouped sections. The grouping should tell users what the product does just by looking at the nav.

```
ANALYSIS
  Dashboard
  Runs
  GEO Analysis

INTELLIGENCE
  Recommendations
  Competitors      (coming soon)

WORKSPACE
  Projects
  Scheduled Runs   (coming soon)

ACCOUNT
  Members
  Settings
```

Coming-soon items are visible but disabled — muted style, tooltip says "Coming soon." Users see what's planned without being able to click into incomplete features.

**Change to `sidebar-nav.tsx`:** Add a `NavGroup` type with a label and items array. Section labels don't get active states — only the individual pages do.

## Sankey chart

On the run detail Evidence tab, add a "Flow" view alongside the existing "Table" view. The default stays as Table.

The flow chart shows how questions moved through AI engines and what came out. Four layers: Questions → Engines → Citation outcome → Sentiment. Width of each band = volume. You can see at a glance where the funnel narrows.

Use `@nivo/sankey` — handles React rendering cleanly.

On mobile, hide the chart entirely with a message: "Open on desktop to see the flow visualization." A Sankey needs enough width to be readable.

If a run has fewer than 3 questions with results, skip the chart and show "Not enough data to visualize."

## CSV exports

Download buttons on existing pages. Each returns a properly named CSV file, generated immediately — no queuing needed.

| Where | What gets exported |
|-------|--------------------|
| Runs list | All runs: id, date, project, scores |
| Run detail → Evidence tab | All AI responses for that run |
| Run detail → Competitors tab | Competitors for that run, including citation share |
| Run detail → Source Intelligence card | Source ecosystem distribution for that run |
| Recommendations page | Open recommendations with issue, scope, action, estimated impact |

## CSV import

Users can bring their own data into a project — topics they care about, competitors they want to track, and custom questions to send verbatim to AI engines.

Import UI lives in project settings, three tabs: Topics, Competitors, Custom Prompts.

**Topics** — questions to track, one per row, optional `type` column:
```
query,type
best oncology pharma companies,discovery
Servier vs Roche,comparison
```

**Competitors** — domains to always track, bypasses auto-detection threshold:
```
domain
roche.com
novartis.com
```

**Custom prompts** — verbatim questions sent as-is to AI engines, not generated by the business understanding step.

UI flow: upload → see first 5 rows as preview → fix any validation errors → confirm. Cap at 500 rows.

**New tables:**

```sql
CREATE TABLE project_topics (
  id          uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  project_id  uuid REFERENCES projects(id) NOT NULL,
  org_id      uuid REFERENCES organizations(id) NOT NULL,
  query       text NOT NULL,
  query_type  text DEFAULT 'user_added',
  source      text DEFAULT 'csv_import'
);

CREATE TABLE project_competitors (
  id          uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  project_id  uuid REFERENCES projects(id) NOT NULL,
  org_id      uuid REFERENCES organizations(id) NOT NULL,
  domain      text NOT NULL,
  source      text DEFAULT 'csv_import'
);
```

The worker reads both tables when building the question list and competitor baseline for a run.
